# 体验微调：心动问候 / 随手记 / 心愿状态机 / 拾光多图 / 我们页信息层级

## Why

v1.0.2 已解决图片上传，但使用体验仍有 6 处不符合直觉：问候语换行且昵称写死、缺少随手记入口、心愿状态无法表达「谁该回应/被拒绝」、拾光页一条记录只露一张图且无法浏览全部、我们页信息层级把同步卡放在头像之上。

## What Changes

1. 心动页问候卡：问候语缩为一行；昵称改为「我的昵称 & 对方昵称」。
2. 新增「随手记」快速记录类型，落到默契页新模块，不进入「最近的美好」。
3. 心愿状态机升级：待回应拆为「待我回应 / 待对方回应」，新增「被拒绝（失效心愿）」，仅「已答应」可标记「已实现」。
4. 拾光页照片卡支持一卡多图（1/2/3/4 张各自的宫格排布）。
5. 点击拾光照片卡 → 全屏多图浏览（左右滑动 + 双指缩放），并保留进入编辑的入口。
6. 我们页：头像卡上移到标语下方；云同步改为与「共同空间/账号与安全/隐私与权限」同列的设置行。

## Impact

- 影响页面：心动、默契、拾光、我们、模块编辑、模块列表。
- 影响数据：新增 `ContentModule.JOT`；心愿 `extra` 新增 `被拒绝` 状态与 `答应人` 落库；`提出人` 改为存 userId（兼容旧值）。
- 不做云端 schema 变更（`module` 与 `extra` 均为文本，服务端不校验枚举）。
- 不改上传/同步协议。

## ADDED Requirements

### Requirement 1：问候卡单行 + 动态昵称

**现状**：`HeartScreen.kt` 调用 `GreetingHero(nickname = "许愿树", partner = "小锦鲤")`；`TimeGreeting.line()` 返回「时段，昵称 & 伴侣」，字号 26/30sp，双昵称时换行。

**目标**
- 问候语固定单行显示，超出以省略号结尾。
- 「许愿树」→ 当前登录用户昵称（`session.nickname`）。
- 「小锦鲤」→ 共同空间对方昵称（`session.partnerNickname`）。
- 未绑定空间时：仍显示自己的昵称 + 「TA」，不出现空白。

**改动点**
- `HeartScreen.kt` L140-149：`nickname = session.nickname.ifBlank { "你" }`，`partner = session.partnerNickname.ifBlank { "TA" }`。
- `HeartScreen.kt` GreetingHero L326-333：问候语 `fontSize` 降到 20sp（`compact` 时 18sp），`lineHeight` 26/24sp，加 `maxLines = 1`、`softWrap = false`、`overflow = TextOverflow.Ellipsis`。
- `TimeGreeting.line()` 格式保持不变（「晚上好，A & B」），仅数据来源变化。

**交互取舍**：不自动缩放字号（避免不同昵称长短导致字号跳动），固定 20sp + 省略号，保证版式稳定；点击卡片仍可编辑问候语。

### Requirement 2：随手记

**目标**：快速记录新增「随手记」，内容归属默契页；不在心动页「最近的美好」出现。

**模块定义**
- `Models.kt` 新增 `JOT(ModuleGroup.TACIT, "随手记", Visibility.COUPLE, needsPhoto = true)`。
- 与 `ROMANTIC_MOMENT` 的区别：仅归属模块不同，「最近的美好」只读 `ROMANTIC_MOMENT`，因此随手记天然不出现（无需额外过滤逻辑）。

**采集入口**
- `QuickRecordTypes.kt`：新增 `const val JOT = "随手记"`，`all` 增加该项（共 6 项），`targetModuleOf(JOT)` 返回 `ContentModule.JOT`。
- `QuickRecordSection`（HeartScreen L846-890）：入口由 5 个变 6 个，改为 **3 列 × 2 行** 网格（`chunked(3)` + 两行 `Row` + `weight(1f)`），保证 48dp 以上点击区、文案不挤压。
- `QuickRecordRouter.targetForLegacyType`：补 `"随手记" -> JOT`（用于旧快速记录迁移）。
- `TacitScreen.kt` L61-72 的 `TacitEntry` 硬编码列表：新增随手记入口（图标用 `Icons.Filled.EditNote` 或现有等价图标），排在「浪漫时刻」之后。

**编辑页**：`ModuleEditScreen` 无需专门分支；`needsPhoto = true` 会自动展示照片区（照片可选，不强制）。

**验收**：随手记保存后出现在默契页模块列表；心动页「最近的美好」不出现。

### Requirement 3：心愿状态机

**现状**：`WishBoard` 只有 待回应/已答应/已实现；`extra["提出人"]` 写死为「我」；`WishCard` 对所有非「已实现」心愿都显示「标记实现」。

**目标状态**
| 状态值 | 含义 | 允许的操作 |
|---|---|---|
| 待回应 | 刚提出 | 由**非提出人**答应/拒绝 |
| 已答应 | 对方已接收 | 任意一方可标记实现 |
| 已实现 | 已完成 | 只读 |
| 被拒绝 | 对方拒绝，归入「失效心愿」 | 只读 |

**视角分组（仅展示层，不落库）**
- 待我回应 = 待回应 且 提出人 ≠ 我
- 待对方回应 = 待回应 且 提出人 = 我
- 已答应 / 已实现 / 失效心愿

**身份判定**
- 新数据：保存心愿时把 `extra["提出人"]` 写成当前 `userId`（在 `AppViewModel.saveRecord` 里统一补写，避免 UI 各自处理）。
- 答应时写入 `extra["答应人"] = 当前 userId`。
- 旧数据兼容：`提出人` 为 `"我"`/空 → 回退用 `record.ownerId`；为 `"TA"` → 视为对方。`WishBoard` 提供统一解析函数，UI 不再直接读 `extra["提出人"]`。

**状态迁移（在 `WishBoard` 内集中校验，非法迁移返回原记录）**
- 答应：仅 `待回应` 且操作者 ≠ 提出人 → `已答应`，写 `答应人`。
- 拒绝：仅 `待回应` 且操作者 ≠ 提出人 → `被拒绝`。
- 实现：仅 `已答应` → `已实现`。
- 其余情况一律不变更（防止旧入口误改）。

**UI 改动**
- `WishBoard.statuses` 改为四个业务状态：待回应/已答应/已实现/被拒绝。
- `HeartScreen.WishSection`：状态 tab 从 3 个变 5 个（待我回应、待对方回应、已答应、已实现、失效）。5 个等分放不下 → 改为**横向可滚动胶囊行**（或两行），每个胶囊显示「标题 数量」。
- 默认选中：有待我回应则选它；否则选待对方回应；再否则已答应。
- `WishCard`：
  - 待我回应 → 显示「答应」「拒绝」两个按钮（拒绝需二次确认）。
  - 待对方回应 → 显示「等待 ${partner} 回应」，无操作按钮。
  - 已答应 → 显示「标记实现」。
  - 已实现 / 被拒绝 → 只读，显示状态徽标。
- `AppViewModel`：新增 `acceptWish` / `rejectWish`；`setWishStatus` 仅在合法迁移时生效（内部走 `WishBoard` 校验）。

**不在本次范围**：被拒绝心愿的「重新发起」、拒绝理由填写。

### Requirement 4：拾光页一卡多图

**现状**：`PhotoTile` 只取 `photo.mediaIds.firstOrNull()` 作为封面，其余图片不可见。

**目标**：一条记录最多 4 张图，按数量排布；无图时保持现有占位图标。

**布局规则（固定 1:1 画布，内部 2×2 宫格）**
- 1 张：占满整张卡片。
- 2 张：左上 + 右下（对角线）。
- 3 张：上排居中 1 张（半宽），下排左右各 1 张。
- 4 张：四宫格填满。

**实现方式**
- 新增纯函数 `GalleryPhotoLayout.cells(count: Int): List<Int>`（返回 0..3 的格子序号），便于单测。
- `GalleryScreen.PhotoTile` 改为按 `cells()` 渲染 4 个格子位，空格保持背景色；各图 `ContentScale.Crop`，格子间 2dp 间隔，整体圆角裁剪保持不变。
- 超过 4 张时只展示前 4 张（编辑页本就限制 4 张）。

### Requirement 5：拾光页多图浏览

**目标**：点击照片卡 → 全屏浏览该记录的全部图片，可左右切换、双指缩放。

**交互**
- 卡片照片区域点击 → 打开 `PhotoPagerDialog(images, initialIndex = 0)`。
- 全屏黑底，`HorizontalPager` 左右滑动；顶部右侧关闭按钮；底部中央「当前/总数」。
- 每页支持双指缩放（复用现有 `ImageViewerDialog` 的缩放参数：0.5x–4x）与拖动；返回键关闭。
- 保留编辑入口：照片卡右下角增加一个 28dp 半透明「编辑」图标按钮，点击进入原「打开记录」逻辑（`onOpenRecord(module, id)`），避免功能回退。

**新增组件**
- `ui/components/PhotoPagerDialog.kt`：参数为图片地址列表、初始页、关闭回调。
- `ui/components/ImageViewerDialog.kt` 可抽出一个可复用的缩放图片 composable，供单图与分页共用。

**空态**：无图记录不打开查看器（保持原行为）。

### Requirement 6：我们页信息层级

**现状顺序**：标题/标语 → 云同步卡 → 头像资料卡 → 设置列表（共同空间、账号与安全、隐私与权限、数据管理、提醒设置、应用设置、个性化偏好）。

**目标顺序**
1. 标题 + 标语 + 通知铃
2. 头像资料卡（紧贴标语下方）
3. 设置列表：共同空间 → 账号与安全 → 隐私与权限 → **云同步** → 数据管理 → 提醒设置 → 应用设置 → 个性化偏好

**云同步行**
- 复用 `SettingRow`，新增可选 trailing 区域（默认无），标题「云同步」，副标题显示：`同步中…` / `上次同步 x 分钟前 · 待上传 N 条` / `尚未同步`。
- 行尾放一个刷新图标按钮，点击 `vm.syncNow()`；同步中图标旋转或禁用。
- 保留原有 `CloudSyncCard` 的状态文案与待上传数逻辑，抽成可复用的状态描述函数，避免两处文案分叉。

原「心愿待实现」三 tab 等分布局，改为五视角可滚动胶囊；数据分组逻辑下沉到 `WishBoard`，UI 只负责渲染。

原「点击 → 打开记录编辑」，改为「点击照片 → 浏览全部图片」，编辑移到卡片右下角图标。

## REMOVED Requirements

### Requirement: 固定问候昵称
**Reason**：写死「许愿树/小锦鲤」与真实账号无关。
**Migration**：改为读取会话昵称，无需数据迁移。

## 验收标准

1. 心动页问候语始终一行，未绑定空间时显示「我 & TA」，绑定后显示双方昵称。
2. 快速记录 6 个入口排布整齐；随手记保存后出现在默契页，且不在「最近的美好」。
3. 心愿：对方提出的心愿出现在「待我回应」并可答应/拒绝；我提出的在「待对方回应」只读等待；拒绝后进入「失效」；只有「已答应」能标记「已实现」；旧数据仍能正确分组。
4. 拾光页 1/2/3/4 张图的卡片分别呈现满图、对角、上一下二、四宫格。
5. 点击照片卡可全屏左右滑动浏览全部图片并缩放；右下角图标仍能进入编辑。
6. 我们页头像卡紧贴标语；云同步以设置行形式位于隐私与权限下方，点击可立即同步。
7. 全量单测通过，`assembleDebug` 构建成功。
