# S520J 运维手册

## 1. 日常操作入口

| 场景 | 操作 |
| --- | --- |
| 部署云函数 | `prepare-functions.js` → `functions:deploy <fn> --force` |
| 执行 SQL | `node cloudbase\scripts\run-sql.js <sql 文件>` |
| 出包 | `scripts\build_apk.ps1 -Tag <tag>`，产物在 `dist/` |
| 查看用量 | CloudBase 控制台 → 环境 → 资源用量（数据库/函数调用/流量） |

## 2. 管理员重置密码

把 `ACCOUNT_ID` 换成账号（8~20 位字母数字），`NEW_PASSWORD` 换成新密码：

```powershell
@"
UPDATE users
SET password_hash = crypt('NEW_PASSWORD', gen_salt('bf')), updated_at = extract(epoch from now())::bigint * 1000
WHERE account_id = 'ACCOUNT_ID';
DELETE FROM auth_sessions WHERE user_id = (SELECT id FROM users WHERE account_id = 'ACCOUNT_ID');
"@ | Set-Content -Encoding UTF8 reset_pwd.sql
node cloudbase\scripts\run-sql.js reset_pwd.sql
Remove-Item reset_pwd.sql
```

重置后该账号所有设备需重新登录。

## 3. 数据库日常维护

- 备份：控制台「数据库 → 备份」开启自动备份（建议每日）。
- 清理：`couple_events` 与 `media_blobs` 会持续增长，建议每季度执行：

```sql
DELETE FROM couple_events WHERE created_at < (extract(epoch from now())::bigint * 1000 - 90*24*3600*1000);
-- 只删无人引用的图片
DELETE FROM media_blobs b WHERE NOT EXISTS (
  SELECT 1 FROM contents c WHERE c.media_refs @> jsonb_build_array(b.id)
);
```

- 用量告警：控制台为「函数调用次数 / 数据库存储 / 出流量」设置告警阈值。

## 4. 客户端数据维护

「我们 → 数据管理」提供：

- 导出数据：JSON + 图片 ZIP（系统文件选择器保存，不加密）
- 手动备份 / 恢复 / 删除：保存在应用私有目录 `filesDir/backups`
- 清理本机数据：只清本机，云端与备份文件保留
- 回收站：删除内容 30 天后物理清除

## 5. 提醒机制

不使用极光/厂商推送。客户端在前台时每 20 秒轮询一次 `event.pull`：

- 有事件 → 顶部横幅 6 秒 + 系统通知（需通知权限）+ 通知中心未读
- 拒绝通知权限 → 仅应用内横幅与未读记录，不再重复弹窗
- 事件游标持久化（`event_cursor`），重装或断网不会重复提醒

## 6. 故障排查

| 现象 | 排查 |
| --- | --- |
| 提示「接口不存在」 | 该 action 前缀未在 `prepare-functions.js` 的 `actionGroups` 中；改完重新 prepare + deploy |
| 提示「请重新登录」 | accessToken 过期且刷新失败；检查 `auth.refresh` 与会话表 |
| 新增内容对方收不到 | 确认已是 `couple` 可见且已绑定；云端核对 `SELECT id,visibility,space_id,updated_at FROM contents WHERE id=...` |
| 改了可见范围对方仍能看到 | 服务端 `syncPull` 的 `revokedIds` 是否返回；客户端拉取后应删除本地副本 |
| 图片不显示 | 检查 `media_refs` 是否为空（旧数据无引用）；`select bytes from media_blobs where id=...`；客户端缓存目录 `filesDir/media` |
| 编辑后云端没变化 | 检查冲突提示；本机 `version` 必须等于云端版本（乐观锁 baseVersion） |
| 同步一直失败 | 设置页「同步诊断」查看 phase；离线时同步会延后重试 |

## 7. 版本发布流程

1. 全量单测：`.\gradlew.bat testDebugUnitTest`
2. 出包：`scripts\build_apk.ps1 -Tag vX.Y.Z`
3. `aapt2 dump badging` 校验 versionName/versionCode
4. 双机实机验收（模板见 `.trae/specs/*/checklist.md`）
5. 验收通过后 Git commit + tag
