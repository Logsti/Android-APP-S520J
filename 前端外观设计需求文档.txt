# S520J 前端外观与交互设计需求文档

**文档版本：** V1.0  
**产品名称：** S520J  
**文档类型：** 前端 UI / UX 外观与交互设计需求  
**设计基准：** 当前网页版交互原型（隐私与个性化完善版）及已确认的后续调整要求  
**适用平台：** 移动端优先，兼容桌面浏览器  
**产品定位：** 两个人的数字生活空间，记录共同生活、珍藏回忆、经营默契与管理共同空间。

---

# 一、产品设计目标

## 1.1 产品定位

S520J 是一款面向情侣的共同生活记录与关系经营应用。

应用以两个人的共同空间为核心，同时保留各自独立的账号、私人内容和个性化设置。

产品整体需要传达以下感受：

- 温暖、自然、轻松。
- 具有生活气息和亲密感。
- 视觉简洁，不堆砌复杂信息。
- 操作直观，符合手机用户的使用习惯。
- 私人内容与共同内容边界明确。
- 让用户能够轻松记录，而不是产生打卡或考核压力。

## 1.2 核心设计原则

1. **移动端优先：** 所有主要页面首先按照手机屏幕设计。
2. **内容优先：** 页面重点突出记录、照片、日历和重要信息。
3. **操作明确：** 可点击模块应有清晰的交互反馈。
4. **隐私优先：** 每条内容都应具有明确的可见范围。
5. **编辑一致：** 同类内容使用统一的新增、查看、编辑和删除操作方式。
6. **视觉统一：** 四个主页面保持一致的配色、卡片、圆角、字体和导航规范。

# 二、整体视觉设计规范

## 2.1 色彩规范

整体采用暖调鼠尾草绿与柔和暖沙色，不使用紫色作为主视觉颜色。

| 用途 | 建议颜色 | 说明 |
|---|---|---|
| 页面背景 | #F8F6EE | 暖白色 |
| 卡片背景 | #FFFEFA | 柔和白色 |
| 主色 | #7D9676 | 鼠尾草绿 |
| 浅绿色 | #D9E5D2 | 柔和浅绿 |
| 沙色 | #EEE4CE | 暖沙色 |
| 主要文字 | #344033 | 深灰绿色 |
| 次要文字 | #858778 | 柔和灰绿色 |
| 分割线 | #E8E2D5 | 浅暖灰 |
| 辅助粉色 | #F2E2D9 | 少量用于温柔提示 |

使用规则：

- 主按钮、选中状态、重点图标使用鼠尾草绿。
- 普通卡片以暖白色为主。
- 日期、纪念日、分类标签可使用暖沙色。
- 私密内容可使用锁形图标或轻量提示，不使用大面积警告色。
- 页面整体保持低饱和度。

## 2.2 字体规范

- 中文主要使用系统默认无衬线字体。
- 页面标题、重要模块标题可使用宋体风格。
- 数字可使用衬线字体增强纪念日、天数等内容的表现力。
- 普通正文应清晰易读。
- 辅助文字不得过小，优先保证手机阅读体验。

## 2.3 卡片规范

- 普通卡片：圆角约 18～24px。
- 大型内容卡片：圆角约 24～30px。
- 圆形图标容器：圆形或圆角胶囊形。
- 卡片使用浅色边框和轻微阴影。
- 避免过重阴影、强烈渐变和复杂装饰。

## 2.4 页面布局规范

- 移动端内容区域应适配屏幕宽度。
- 页面左右留白保持统一。
- 卡片之间保留足够间距。
- 页面内容支持自然纵向滚动。
- 底部导航固定显示，并考虑手机安全区域。
- 弹窗应适配小屏幕，避免键盘遮挡输入区域。

# 三、整体页面结构

应用采用四个固定主导航页面：

| 页面 | 名称 | 核心作用 |
|---|---|---|
| 第一页 | 心动 | 日常互动、共同计划、快速记录 |
| 第二页 | 拾光 | 照片、做饭、探店及生活回忆 |
| 第三页 | 默契 | 重要日子、承诺、偏好和相处记录 |
| 第四页 | 我们 | 个人资料、共同空间、隐私和应用设置 |

## 3.1 底部导航

四个导航入口：

- ♡ 心动
- ▧ 拾光
- ✧ 默契
- ♙ 我们

设计要求：

- 固定在屏幕底部。
- 当前选中页面使用鼠尾草绿。
- 未选中页面使用灰绿色。
- 图标与文字上下排列。
- 导航栏使用暖白半透明背景。
- 切换页面时保持简洁、自然的反馈。

## 3.2 页面新增按钮

- 全局不再统一显示右下角新增按钮。
- 仅第二页「拾光」保留悬浮新增按钮。
- 第一、第三、第四页不显示右下角悬浮加号。
- 其他页面的新增操作应放在对应模块内部，避免误操作。

# 四、第一页：心动

## 4.1 页面定位

心动页面是应用的日常首页。

重点是让两个人快速查看今日互动、共同愿望、日历和最近的生活记录。

页面内容按以下顺序排列：

1. 今日心动挑战
2. 快速记录
3. 心愿待实现
4. 碰碰你
5. 共同日历
6. 最近的美好

页面顶部保留情侣问候与相伴天数展示。

## 4.2 顶部问候卡片

展示内容：

- 当前日期和星期。
- 两个人的问候语。
- 双方昵称。
- 相伴天数。
- 一句日常寄语。

视觉要求：

- 使用鼠尾草绿到暖沙色的柔和渐变。
- 大圆角卡片。
- 白色文字。
- 相伴天数使用较大字号。
- 卡片整体温暖、简洁。

交互要求：

- 点击后可编辑问候语。
- 可调整昵称展示。
- 相伴日期等计算基础信息需要有明确的数据来源。

## 4.3 今日心动挑战

展示内容：

- 挑战名称。
- 挑战描述。
- 标签。
- 换一换入口。
- 标记完成按钮。
- 温柔的辅助提示。

交互要求：

- 可以更换每日挑战。
- 可以编辑挑战内容。
- 双方可分别确认完成状态。
- 不设置惩罚、连续打卡或关系考核。
- 未完成时不显示负面警告。

## 4.4 快速记录

提供五个快捷入口：

- 照片
- 做饭
- 探店
- 文字
- 浪漫时刻

交互要求：

- 点击后进入对应的新增记录界面。
- 需要照片的内容提供图片选择入口。
- 纯文字内容不强制上传照片。
- 保存前允许调整可见范围。

## 4.5 心愿待实现

以横向滑动卡片展示心愿。

每张卡片包含：

- 心愿内容。
- 提出人。
- 对方回应状态。
- 期望完成时间。
- 标记实现入口。

交互要求：

- 可以新增、编辑、删除心愿。
- 可以查看全部心愿。
- 支持待回应、已答应、已实现等状态。
- 双方可以查看共同心愿。

## 4.6 碰碰你

默认互动：

- 拍一拍
- 抱抱
- 亲亲
- 想你

新增 DIY 功能：

- 用户可以添加自定义互动名称。
- 用户可以删除自定义互动。
- 自定义项目展示在默认互动之后。
- 自定义项目应有清晰的发送反馈。
- 不限制情侣创建专属互动名称。

## 4.7 共同日历

日历是首页的重要功能模块。

展示要求：

- 完整显示当前月份。
- 显示星期标题。
- 显示完整日期网格。
- 当前日期突出显示。
- 有事项的日期显示标记。
- 日期可以点击选择。
- 支持前后月份切换和返回今天。

日历下方展示所选日期对应的：

- 待办事项。
- 重要时间。
- 纪念日。
- 共同计划。

交互要求：

- 点击日期切换事项列表。
- 可以新增待办事项和重要时间。
- 可以编辑和删除事项。
- 事项支持日期、标题、类型和备注。
- 双方可查看共同日历内容。

## 4.8 最近的美好

以纵向卡片列表展示最近记录。

记录内容包括：

- 事件标题。
- 创建者。
- 创建时间。
- 相关照片或图标。

点击记录后进入详情或编辑界面。

# 五、第二页：拾光

## 5.1 页面定位

拾光用于收藏两个人共同经历的生活片段。

该页面保留已确认的照片墙视觉样式，不随其他页面改版而改变。

## 5.2 页面顶部

顶部文案：

**拾起生活里的微光。**

副标题：

照片、味道、去过的地方，都值得被好好收藏。

顶部保留日期卡片。

该区域只在第二页「拾光」中出现，其他三个页面不显示。

## 5.3 四个核心模块

页面顶部设置四个统计入口：

1. 共同照片
2. 一起做过的菜
3. 一起去过的店
4. 收藏的瞬间

四个模块都必须可以点击。

点击后进入独立内容管理页面，而不是仅展示统计数字。

### A. 共同照片

内容字段：

- 照片。
- 标题。
- 拍摄日期。
- 地点。
- 照片说明。
- 创建者。
- 可见范围。

功能：

- 新增照片。
- 查看照片详情。
- 编辑照片信息。
- 删除照片。
- 搜索和筛选。
- 按日期、地点和分类浏览。

### B. 一起做过的菜

内容字段：

- 菜品名称。
- 成品照片。
- 制作日期。
- 制作人。
- 食材。
- 制作步骤。
- 口味评价。
- 是否愿意再次制作。

功能：

- 新增菜品记录。
- 上传照片。
- 编辑食材和步骤。
- 查看历史记录。
- 删除记录。
- 搜索菜品。

### C. 一起去过的店

内容字段：

- 店铺名称。
- 店铺照片。
- 地址或地点。
- 到访日期。
- 消费情况。
- 品尝菜品。
- 体验评价。
- 星级。
- 是否愿意再次前往。

功能：

- 新增探店记录。
- 上传照片。
- 编辑店铺信息。
- 查看历史评价。
- 删除记录。
- 按地点和日期筛选。

### D. 收藏的瞬间

内容字段：

- 瞬间标题。
- 照片或插图。
- 发生日期。
- 地点。
- 记录故事。
- 创建者。
- 可见范围。

功能：

- 新增瞬间。
- 查看详情。
- 编辑内容。
- 删除记录。
- 收藏和筛选。

## 5.4 照片墙

保留现有照片墙设计：

- 双列瀑布式或双列卡片布局。
- 大尺寸彩色图片区域。
- 图片下方展示标题和分类标签。
- 卡片使用大圆角。
- 不同记录可以采用不同的柔和背景色。
- 私密记录显示锁形标记。

分类包括：

- 全部
- 做饭
- 探店
- 旅行
- 日常
- 纪念日

## 5.5 五星榜

保留双方独立的五星榜入口。

- 小锦鲤五星榜。
- 许愿树五星榜。

用于收藏彼此喜欢的菜品、餐厅和体验。

不得用于评价对方的人格或关系表现。

## 5.6 新增入口

第二页右下角保留悬浮加号。

点击后提供新增记录入口。

根据新增内容类型，自动决定是否显示照片上传选项。

# 六、第三页：默契

默契页面用于整理两个人的重要日子、彼此承诺、相处习惯、偏好以及私人记录。

页面强调内容分类和隐私管理。

## 6.2 八个子模块

八个模块必须全部具有独立入口：

1. 重要日子
2. 彼此的承诺
3. 为彼此做过
4. 浪漫时刻
5. 相处之道
6. TA 的喜欢
7. TA 不喜欢
8. 我们的笔记

## 6.3 页面展示方式

- 八个模块使用圆形图标入口。
- 页面上方展示八个模块入口。
- 八个入口应支持横向滑动查看。
- 入口保持统一尺寸和图标风格。
- 选中状态使用鼠尾草绿。
- 不采用大量纵向展开内容挤占首页空间。

预览区域随选中模块切换，展示该模块的少量最新记录。

## 6.4 独立模块详情页

点击任意一个模块，必须进入该模块独立的内容管理页面。

每个详情页应提供：

- 模块标题。
- 内容列表。
- 新增入口。
- 搜索入口。
- 查看详情。
- 编辑。
- 删除。
- 可见范围设置。
- 空内容提示。

详情页应支持独立滚动，不影响主页面的其他模块。

# 八、账号注册与情侣共同空间绑定

此部分是已提出的下一轮功能需求，需在前端实现独立流程。

## 8.1 账号注册

提供注册页面，字段包括：

- 昵称。
- 邮箱。
- 密码。
- 确认密码。

交互要求：

- 必填项校验。
- 邮箱格式校验。
- 密码长度校验。
- 注册成功反馈。
- 错误信息提示。
- 注册后进入登录状态。

## 8.2 账号登录

提供：

- 邮箱。
- 密码。
- 登录按钮。
- 注册入口。

支持登录失败提示和登录成功状态。

## 8.3 情侣共同空间绑定

支持两种流程：

**创建共同空间：**

1. 用户创建共同空间。
2. 系统生成唯一邀请口令或邀请链接。
3. 用户分享给另一半。
4. 另一半登录自己的账号。
5. 输入口令或打开邀请链接。
6. 双方确认绑定。

**加入共同空间：**

1. 用户登录独立账号。
2. 输入另一半的邀请码。
3. 查看空间信息。
4. 确认加入。
5. 绑定成功后进入共同空间。

## 8.4 绑定状态

需要区分：

- 未绑定。
- 已生成邀请。
- 等待对方加入。
- 绑定申请中。
- 已绑定。
- 绑定失败。

## 8.5 账号与空间关系

- 每个人拥有独立账号。
- 一个共同空间最多绑定两名成员。
- 两个人的个人账号不合并。
- 共同内容在双方账号中可见。
- 私人内容仍然归创建者个人所有。

# 九、内容新增、查看、编辑与删除规范

## 9.1 通用操作流程

所有可管理模块遵循统一交互：

1. 进入模块。
2. 查看内容列表。
3. 点击新增。
4. 填写内容。
5. 根据需要上传照片。
6. 选择可见范围。
7. 保存。
8. 返回列表查看新内容。

点击已有内容：

- 进入详情。
- 查看完整信息。
- 点击编辑修改内容。
- 点击删除时进行二次确认。

## 9.2 照片上传规则

需要照片的内容：

- 共同照片。
- 做饭记录。
- 探店记录。
- 浪漫时刻。
- 重要回忆。
- 其他用户主动选择添加照片的记录。

不强制要求照片的内容：

- 文字笔记。
- 偏好记录。
- 承诺。
- 相处约定。
- 日历待办。
- 心愿。

照片字段应支持预览、替换和删除。

## 9.3 内容可见范围

每条内容均应具有独立可见范围：

| 可见范围 | 说明 |
|---|---|
| 仅自己可见 | 只有创建者本人可以查看 |
| 双方可见 | 共同空间双方均可查看 |
| 指定授权 | 仅授权对象可以查看 |

初始建议：

- 拾光中的共同照片、做饭和探店：默认双方可见。
- 心动中的共同日历和心愿：默认双方可见。
- 默契中的私人笔记、偏好、承诺等：按具体内容默认设置，允许用户调整。
- 关于 S520J：固定只读。

前端选择可见范围后，正式版必须由服务端进行权限校验。

# 十、编辑权限与只读规则

## 10.1 可编辑内容

- 主题。
- 字体。
- 语言。
- 个性化设置。
- 问候语。
- 心愿。
- 日历事项。

- 做饭记录。
- 探店记录。

## 10.2 只读内容

只读内容不应显示编辑、删除等操作入口。

# 十一、响应式与移动端适配

## 11.1 手机端

手机端为第一优先级。

要求：

- 页面内容不出现横向溢出。
- 卡片宽度根据屏幕自适应。
- 底部导航固定。
- 重要操作按钮便于单手点击。
- 弹窗适配系统键盘。
- 日历完整显示当前月份。
- 横向模块滑动时不能影响页面纵向滚动。

## 11.2 桌面端

桌面端保留手机端的整体视觉比例。

- 主内容区域居中。
- 页面最大宽度建议约 430px。
- 设置合理的外部留白。
- 弹窗在桌面端垂直居中。
- 不因屏幕变宽而无限拉伸卡片。

# 十二、交互反馈规范

所有可点击元素都应有明确反馈：

- 点击按钮：轻微状态变化。
- 页面切换：选中状态更新。
- 保存成功：轻提示。
- 删除操作：二次确认。
- 输入错误：明确指出问题。
- 图片上传：展示预览。
- 空列表：展示友好空状态和新增入口。
- 网络失败：提供重试提示。

不允许出现看起来可以点击、实际上没有任何操作反馈的控件。

# 十五、最终设计目标

S520J 的最终界面应当是一款温暖、简洁、具有生活质感的情侣共同空间应用。

四个页面各有明确定位：

- **心动：** 让日常互动和共同计划变得轻松。
- **拾光：** 收藏一起经历的生活。
- **默契：** 整理彼此的了解、承诺与回忆。
- **我们：** 管理双方资料、共同空间和应用设置。

所有模块都应做到入口清晰、操作自然、内容可管理、隐私可控制。

最终效果以当前已确认的网页版视觉风格为基础，不随功能增加而破坏整体设计的一致性。
